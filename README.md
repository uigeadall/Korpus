# Корпус

Сайт и конфигуратор за корпусна мебел по индивидуален проект. Клиентът чертае
жилището си, избира стая и отговаря на няколко въпроса; правилата подреждат
мебелта, смятат обкова и изкарват разбивка за цеха.

`Корпус` е работно име — марката още не е избрана. Сменя се на едно място:
`src/config/brand.ts`.

---

## Пускане

```bash
npm install
npm run dev          # http://localhost:3000
```

```bash
cp .env.example .env.local    # ключовете, ако ги има
```

Нужен е Node 20 или по-нов. Няма ключове и няма база — всичко живее в браузъра,
докато акаунтите на фирмата не влязат (виж `docs/PLAN.md`, етап 0).

## Проверки

```bash
npm run typecheck    # tsc
npm run lint         # eslint
npm test             # vitest — правилата
npm run test:e2e     # playwright — браузър, десктоп и телефон
npm run test:all     # двете наведнъж
```

Първото пускане на `test:e2e` иска браузър: `npx playwright install chromium`.
Сървърът се вдига сам; ако вече върти `npm run dev`, ползва него.

## Как е устроено

**Правилата са чист TypeScript и се проверяват с тестове. React само рисува.**
Това е първото правило на проекта и всичко останало следва от него.

```

  cabinet-rules.ts       размери, каталог на модулите, обков, разбивка
  furniture/             общият слой: система, кутии, детайли, стая
  openings.ts            врата и прозорци на стаята
  flat.ts                жилището: стаи, съседи, врати между тях
  flat-furniture.ts      мебелта на стаите, сложена в макета
  zapitvane.ts           какво приема вратата за запитвания
  autolayout.ts          отговорите на въпросите → подредени модули
  drop3d.ts              къде ляга модул, пуснат с показалец в обема
  render.ts              кадърът като картинка: материали, дълбочина, части
  opisanie.ts            проектът, казан с думи — за модела и за човека
  skica.ts               какво приема вратата за снимки
  skica-model.ts         моделът зад гнездо; днес Gemini 2.5 Flash Image
  slide.ts               шкаф, плъзнат по стената; празното става ниша
  scene3d.ts             обемите на стаята; flat-scene.ts — на жилището
  drawing.ts             геометрията на фронталния чертеж
  wall-finish.ts         кое покритие е на коя стена; wall-pattern.ts — шарката му
  fit.ts                 мебелта се побира — нищо не минава през стената
  slide.ts               шкаф по стената по решетка
  zoom.ts                приближаване към точката под мишката
  price.ts               ориентировъчната цена от разбивката
  elevation.ts, homography.ts   мебелта върху снимка на стената
  flat-furniture.ts      мебелта на готовите стаи в макета на жилището
  share.ts               проектът, побран в линк; flat-share.ts — жилището
  pdf/, xlsx.ts          файловете за клиента и за цеха

src/components/
  proekt/                воденият поток — входната врата за клиента
  flat/                  чертежът на жилището
  configurator/          техническият инструмент (вътрешен)
  site/                  общото за публичните страници; tema.ts — светла/тъмна

src/i18n/                езиците — български, английски, китайски
  ezik.ts                кои са, адресите им (`/en/…`, `/zh/…`)
  tekstove/              текстовете по раздели, трите езика един до друг
```

### Екраните

| Адрес | За кого |
|---|---|
| `/` и статичните страници | публичният сайт |
| `/jilishte` | клиентът чертае жилището и обикаля стаите |
| `/proekt` | воденият поток за една стая |
| `/konfigurator` | **вътрешен инструмент** — милиметри и разбивка за цеха; няма го в менюто и не се индексира |

### Езиците

Български, английски и китайски, с меню горе вдясно. Българските адреси
са без префикс и не са се променили (`/proekt`); другите са под своя код
(`/en/proekt`, `/zh/proekt`). Изборът от менюто се помни в бисквитка
`korpus-ezik`, така че пратен български линк се отваря на избрания език.

- **Нов текст** влиза в `src/i18n/tekstove/` на трите езика наведнъж —
  сборката пада, ако някой липсва. Компонентът го чете с `useT(…)`
  (клиентски) или `getT(…)` / `getEzik()` (сървърни).
- **Ново име в правилата** (модул, цвят, покритие) влиза и в
  `src/i18n/rechnik.ts`. Правилата остават на български: имената им са
  ключ в линковете и в разбивката за цеха. Тест пази всяко име от
  каталозите да има превод.
- **Вътрешна връзка** — през `@/i18n/Link` или `useAdres()`, за да води
  на същия език. Линковете за споделяне остават без префикс.
- **На български остават:** панелите на конфигуратора (вътрешен инструмент), PDF-ът и XLSX-ът
  за цеха и описанието, което отива към модела за снимки.

## Правила, които спазваме

1. Всичко, което трябва да е вярно, е чист TypeScript с тестове. React само рисува.
2. Нова формула → първо контролна стойност от мебелиста, после код.
3. `RULES_VERSION` се вдига при всяка промяна на формулите. Проект от по-стари
   правила се отваря с бележка, че е пресметнат наново — старите формули не се
   пазят и мълчаливото преизчисляване би било лъжа.
4. Никакви тайни в git. Ключовете се четат от средата и не напускат
   сървъра. Реални имейли и SMS само след изрично „да".
5. Правните текстове стоят маркирани като чернови до преглед от юрист.
6. Едно нещо се прави на едно място. Два бутона за едно и също се махат.
